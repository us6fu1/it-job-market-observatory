# Методика расчётов

Проект различает три показателя:

- новые вакансии - объявления с датой публикации внутри периода;
- доступные вакансии - объявления, попавшие в конкретный снимок поиска;
- уникальные объявления - разные `vacancy_id` за выбранный период.

Эти числа нельзя смешивать. Например, одна вакансия может находиться в пяти
ежедневных снимках, но остаётся одним уникальным объявлением.

## Зарплата

Границы, валюта, gross/net и период выплаты хранятся отдельно. Если указана
только одна граница, она не превращается в среднюю зарплату. Медиана середины
вилки считается только по вакансиям с двумя границами и отдельно по валютам.
Рядом всегда показывается покрытие зарплатными данными.

В API «Работа России» нулевая граница зарплаты означает отсутствие значения и
преобразуется в `NULL`. Если верхняя граница положительная, но меньше нижней,
она также не используется, а причина сохраняется в метаданных нормализации.

## Жизненный цикл

Исчезновение из поиска означает только `not_seen_in_latest_search`. Оно не
доказывает закрытие. Подтверждённый статус должен появляться после отдельного
запроса карточки и записываться в `fact_vacancy_status_check`.

## Ограничения

История начинается с первого запуска проекта. Данные до этой даты не
восстанавливаются. Поиск HH ограничен глубиной 2 000 результатов, поэтому журнал
сегментов нужно проверять после каждого запуска. Демонстрационные файлы в
`data/sample` полностью вымышлены и не подходят для выводов о рынке.

Открытый API «Работа России» используется для проверки живого конвейера без
токена. Параметры `modifiedFrom` и `modifiedTo` ограничивают дату последнего
изменения записи, а не дату её первоначальной публикации. Его текстовый поиск
возвращает много нерелевантных профессий. Перед сохранением в RAW заголовок
вакансии проверяется по регулярным выражениям из
`config/trudvsem_segments.json`. В аудите отдельно сохраняются число результатов
источника и число строк, прошедших фильтр.

В RAW для этого источника хранится общая модель и обезличенная копия полей
исходной записи. Поля с телефонами, электронной почтой и контактными лицами
удаляются до записи на диск и в PostgreSQL.

Поле навыков у источника заполнено не в каждой вакансии. Проект дополняет его
только явно найденными названиями технологий из небольшого словаря в
`ingestion/trudvsem_client.py`. Такой результат нельзя считать полноценным NLP-
анализом текста.

Контактные данные соискателей и представителей работодателя не переносятся в
общую модель и не сохраняются в аналитических слоях.
